# Changelog

## 0.2.0 — policy and evidence source foundations (candidate)

### Added
- Deterministic common→role→client policy compilation, protected precedence, narrowing/revocation, explicit expiring exceptions, declared host/VM placement checks, content-hashed snapshots and report-only drift.
- `deploy --check-policy` reports refusals without contacting or changing hosts. Host placements shared by multiple clients are ambiguous rather than last-write-wins; every duplicate enrolled-identity claimant is refused; missing/blank/non-string roster roles cannot bypass admission.
- Tenant-scoped logical append-only journal with process-held OS locks, crash release, atomic fsynced publication, torn-tail refusal and reference-only evidence. Persisted rows are shape-validated on locked reads (`JournalCorrupt` names store/line/field, never payload); only the owning process/thread reuses a held transaction. Readiness uses lock-assigned commit sequences (max+1 across valid gaps), never display dates: each incident needs a later committed resolved repair of its own chain. Current promotion readiness is separate from historical approval-sequence completion; CLI answers use one locked snapshot and approvals recheck under lock. Caller-garbage dates are typed `RecordError`; native Windows open-handle replace refusals are `JournalLocked`, preserve prior bytes, and leave no temp debris. Tenant aliases/devices/unsafe suffixes are refused without normalizing identifiers. Publication is process-crash durable; power-loss durability and directory fsync are not claimed.
- Repairs, recurrences and lesson bases cannot reference another subject at append; rejected writes preserve prior bytes. Other-subject legacy recurrences cannot affect readiness.
- Exception records require a non-empty path and string approver, without relaxing temporal/protected-capability checks.
- GLM closeout findings: broader lower-layer protection now survives the fold; only redundant subsets/aliases can be omitted. Constrained lower grants now emit the narrowed coverage, not the upper layer's broad paths. Reserved UNC anchor components, client-only role selectors in role files and unknown exception keys are refused.
- Opus B146 confirms both fold defects and adds duplicate exception IDs: duplicate IDs are now refused per client before activation or drift, for files and direct-source callers. Protected-path drift compares effective coverage rather than spellings; aliases and expanded protection do not falsely report a removal, while original spellings still affect snapshot integrity. Corrected review evidence includes the actual roster loader and error class, previously omitted.
- Opus B439 gives source SHIP with minor follow-ups. The report-only roster boundary now requires boolean execution flags and refuses read/decode failures contextually; a string "false" cannot earn ALLOW and no loader traceback is exposed for unreadable/non-UTF-8 input. These loader changes postdate B439 review and still require closeout.
- Explicit report-only roster selections now read exactly the selected file or refuse; a missing CLI/environment path cannot silently select a working-directory roster. Still-declared inactive exceptions are not misreported as operator deletion. Path syntax now explicitly documents the existing forward/backslash UNC namespace versus single-leading-slash POSIX paths; UNC support is preserved, not removed to silence review. ALLOW/path and drift-exit semantics are explicitly non-enforcing/non-gating.
- GLM B455 identified a UTF-8 refusal gap in the policy/snapshot sibling readers. Both now translate decoding failures into file-named `PolicySourceError`; real API/compile/gate/drift coverage across common/role/client sources and snapshots reproduced 11 failures plus one valid-Unicode positive control before correction, then all 12 passed.
- GLM B467 identified non-finite snapshot JSON reaching hashing. Both readers now validate parsed values against the canonical UTF-8 representation, refusing NaN/Infinity, overflowed exponents and escaped lone surrogates contextually. Consumed snapshot grant/path/exception shapes are validated before drift operations. Actual snapshot write failures now become typed refusals after temporary-file cleanup, preserving existing destination bytes. The original boundary matrix reproduced 40 failures with 7 positive controls; adjacent nested-shape tests reproduced 22 further failures before correction. Forward-UNC anchor allegations were refuted on both real interpreters and pinned by six separator-alias refusal controls.
- Opus B536 identified CPython integer-digit and recursion-limit errors escaping parsing. Policy sources and snapshots now share a parser/value-validation boundary; syntax errors retain line-number diagnostics, plain parser `ValueError` and parse/canonicalization `RecursionError` become contextual domain refusals. The report-only roster wrapper translates these errors for both explicit and discovered rosters, without changing legacy delivery behavior. All 31 real API/compile/gate/drift/roster/canonicalizer cases failed before correction, then passed.
- GLM B536 flagged undocumented naive approval-time semantics. New source exceptions now require an explicit UTC offset for both approval and expiry, for files and direct callers; historical snapshot drift preserves UTC compatibility. Equivalent Z/+14:00/-14:00 windows are tested at exact expiry. Eight source refusal cases failed before correction with four positive/history controls passing; all 12 now pass. Nine additional real source API/compile/gate cases exercise noncanonical JSON tokens directly. The protected-path subsumption allegation is refuted by the unchanged implementation returning only the ancestor.
- B567 both reviewers give source SHIP. GLM's direct-caller encoding parity follow-up is now fixed: in-memory sources pass the same canonical UTF-8 validation before the fold; six surrogate-path/capability cases failed before correction and all seven cases including valid Unicode now pass. Roster tests now require the parser-limit reason, not merely any refusal; actual poisoned parent-environment runs pass on both native OSes. The env-inheritance allegation is refuted rather than patched with redundant environment handling.
- Both E closeout reviewers found missing persisted-store uniqueness and reference type guards. Every data/approval read now validates unique IDs and positive commit sequences; malformed references/kinds and approval history are refused before lookup/readiness. Invalid UTF-8 stores are corruption, invalid caller files are CLI usage errors, explicit empty approval dates are not defaulted, and tenant control characters are refused before I/O. Existing gap-repaired histories remain readable without optional display dates.
- Opus E410 closeout found escaped lone-surrogate strings reaching UTF-8 publication. Recursive string validation now covers record/approval values and keys, nested evidence/references, tenant names and persisted rows; caller input is a typed refusal and stored invalid strings are corruption. Readers decode raw bytes so a bare CR cannot impersonate a committed newline; complete CRLF legacy lines and valid Unicode remain supported.

- GLM E410 tenant-normalization finding is reproduced on real APFS against pristine source: differently spelled handles read the same store. Admission now inspects stored entries after exclusive creation and conservatively refuses NFC/case aliases without normalizing tenant identities. Parent fixes additionally prefer any alias over an exact entry, close directory scans, and remove only newly created empty alias directories on normalization-sensitive volumes. Same-spelling reopen and prior bytes remain intact.
- Approval `(subject, stage)` uniqueness is now validated on every locked approval read and the pure promotion consumer, with typed shape checks before hashing. Parent CLI fixes translate constructor and real operation-time path failures without a synthetic pre-acquire/release; corrupt/locked/gate refusal remains exit 1, path/input refusal exit 2. JSON parser limits and non-finite metrics are refused in both stored and caller paths.

- Opus E639 gives source SHIP, but its duplicate-key follow-up was reproduced by the parent: an ambiguous fourth approval row is accepted as a complete recorded sequence. Both stored JSONL and CLI input now reject repeated object keys at all nesting levels; pure promotion rows require all four approval string fields before indexing. Seven new cases failed before correction with one positive control, then all eight passed. This is report integrity, not authenticated execution authority.

- GLM E639 flagged an overbroad exact-reopen promise. A real mounted case-sensitive APFS probe confirms both legacy folding siblings are refused, their bytes unchanged, and conflict-free exact reopen works. This is the intended portable admission boundary; documentation now states it without weakening refusal to prefer an exact entry. A two-case native-volume/path matrix pins conservative refusal and real directory-loss behavior. The API lock-open path previously leaked FileNotFoundError after admission; it now raises JournalPathRefused and releases the in-process lock for immediate reuse. CLI corrupt/path exit documentation is explicit.
